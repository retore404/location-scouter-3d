# Design

## Context

- リポジトリにはまだアプリのコードがない。`pnpm-workspace.yaml` は `frontend` と `tools/*` を宣言済みで、ルートには oxlint（React プラグイン有効、React 19.2 系を想定）・oxfmt・knip・vitest の設定がある。
- データは PLATEAU 配信サービスを直接使う（proposal.md - What Changes）。事前に確認できた事実は次のとおり。
  - データカタログの GraphQL API（`https://api.plateauview.mlit.go.jp/datacatalog/graphql`）は CORS を許可している（`access-control-allow-origin: *`）。`datasets(input: {areaCodes, includeTypes: ["bldg"]})` で、区ごと・LOD 別の `tileset.json` の URL を取得できる。応答の大きさは東京23区で約17KB、横浜市で約8KB。REST の全件カタログは約9MBあり、実行時の取得には向かない。
  - 建物の 3D Tiles の配信元も CORS を許可している。
  - 建物 LOD1 は東京23区・横浜市の全区にある。LOD2 以上は区によって有無が異なり、横浜市は5区のみ。
  - 建物の 3D Tiles は「日本のジオイド2011」で楕円体高に変換済み。
  - 地形は PLATEAU 配信サービスが quantized-mesh 形式で配信している（`https://tile.plateauview.mlit.go.jp/terrain/layer.json`）。楕円体高で、CORS を許可しており、Cesium ion のトークンは不要。PLATEAU のドキュメントはこちらを推奨し、Cesium ion 経由の PLATEAU-Terrain は旧来の配信としている。
  - どちらのサービスも試験運用で、提供期間とサービスレベルの保証はない。

## Goals / Non-Goals

**Goals:**

- 撮影地点・花火の位置と大きさの計算を、描画ライブラリから切り離した純粋な関数として持ち、単体テストで検証できるようにする。
- 建物・地形・開花範囲の高さを、楕円体高という1つの基準で扱う。

**Non-Goals:**

- オフライン動作、データのキャッシュ・自前ホスティング。
- 画面の状態の保存（再読み込みで消えてよい）。
- E2E テストの自動化。動作確認は手動で行う。

## Decisions

### 1. フロントエンドは Vite + React + TypeScript、3D 描画は CesiumJS を直接使う

- CesiumJS は、3D Tiles・地形・地球の丸み・楕円体高の座標系を標準で扱える。代替の Three.js + 3d-tiles-renderer では地理座標と地形を自前で扱う必要があり、deck.gl / MapLibre では視点を自由に動かせない。
- React は既存の oxlint 設定が前提にしているため採用する。
- Resium（CesiumJS の React ラッパー）は使わない。CesiumJS の Viewer を1つのコンポーネントで保持し、React の状態から Cesium の表示へ一方向に同期する。Cesium のカメラ操作とイベントは命令的な API で扱うため、ラッパーを挟むと制御が二重になる。
- Cesium の静的アセット（Workers / Assets / Widgets / ThirdParty）は、Cesium 公式の Vite 構成例と同じく、ビルド時に配信ディレクトリへコピーし `CESIUM_BASE_URL` で参照する。

### 2. 状態とモジュールの分け方

```
frontend/src/
  domain/   撮影地点・花火・号数の目安値・入力値の検証・最も近い花火の選択など（純粋な関数。Cesium に依存しない）
  geo/      緯度経度・楕円体高と視線の向き（方位・仰角）の変換（Cesium の数学関数を使う純粋な関数）
  data/     データカタログ API の呼び出しと tileset URL の選択
  map/      Cesium Viewer の生成、レイヤーの追加、状態から表示への同期、クリックやカメラ操作の処理
  ui/       パネル、入力欄、モード切り替え、注記、エラー表示
```

- アプリの状態（モード、配置中の道具、撮影地点、花火の一覧、データ取得エラー）は `useReducer` で1か所に持つ。外部の状態管理ライブラリは導入しない。
- `map/` は状態を読んで Cesium の Entity とカメラに反映し、クリックの結果を action として返すだけにする。状態の正は React 側に置く。

### 3. 建物は LOD1 を、実行時にカタログ API から取得して表示する

- 起動時に GraphQL API へ、東京23区（地域コード 13101〜13123）と横浜市（14100）の `bldg` を問い合わせる。各区について LOD1 の `tileset.json` を選び、`Cesium3DTileset` として追加する。
- LOD1 を選ぶ理由: 全区にあり、カバー範囲が揃っている。LOD2 は区によって欠けていて、LOD1 と重ねると表示が干渉する。遮蔽の判定には、建物の高さを持つ LOD1 の箱型で足りる。
- URL を固定値として埋め込まない理由: 配信 URL は予告なく変わり得るため。ただし、カタログ API の応答の形が変わることには備えない（試験運用のサービスに追従する変更として、別途扱う）。

### 4. 地形は PLATEAU 配信の quantized-mesh、背景地図は地理院タイル

- 地形は PLATEAU 配信サービスの quantized-mesh を `CesiumTerrainProvider.fromUrl` で読み込む。Cesium ion 経由の PLATEAU-Terrain は、トークンと Cesium ion の利用条件への依存が増えるうえ、PLATEAU 側でも旧来の配信とされているため使わない。
- Cesium ion は一切使わない。既定の背景画像・地名検索などの Viewer の既定のウィジェットを無効にする。
- 地形の出典（PLATEAU | Mapterhorn | 国土地理院）は `layer.json` の `attribution` に含まれ、Cesium のクレジット表示に出る。背景地図は、川や海の位置がわかりやすい国土地理院の淡色地図タイルを使い、出典を表示する。
- `scene.globe.depthTestAgainstTerrain` を有効にし、地形が開花範囲を遮るようにする。

### 5. 高さはすべて楕円体高で扱い、地上高から変換する

```
  表示する高さ (楕円体高) = その緯度経度の地表の楕円体高 + 地上高 (撮影地点) または 開花高度 (花火)
```

- 地表の楕円体高は、地点を置いたとき・緯度経度を変えたときに、地形データから取得する（`sampleTerrainMostDetailed`）。取得が終わるまでは、その地点を表示しない。
- 地形を取得できない場合は、地表の楕円体高を 0m とみなす。仕様どおり、高さが実際と異なり得ることを画面に表示する。
- 撮影地点を建物の屋上でクリックした場合でも、使うのは緯度経度だけにする。高さはユーザーが地上高で入力する（展望フロアの高さは建物の高さと一致しないため）。

### 6. 一人称モードは Cesium の標準カメラ操作を無効にして、視線の向きだけを変える

- 一人称モードに入ると、`screenSpaceCameraController` による移動・ズーム・傾きを無効にする。ドラッグとスワイプの移動量を方位・仰角の変化に変換し、`camera.setView` で位置は撮影地点のまま向きだけを更新する。
- 仰角は -90°〜90° の範囲に制限する。
- 視野角は Cesium の既定値のままにする。レンズの画角は #4 で扱う。
- 開始時の向き: 撮影地点から最も近い花火の開花範囲の中心への方位・仰角を `geo/` で計算する。距離は撮影地点と開花範囲の中心の直線距離で比べる。

### 7. 開花範囲は半透明の球の Entity で描画する

- 各花火を、打上地点の印（地表に固定した点）と開花範囲の球（`EllipsoidGraphics`、半透明の単色）の2つの Entity で表す。
- 不透明な建物と地形は先に深度が書き込まれるため、遮られた部分の球は描かれない。これが仕様の「遮られた部分は表示されない」にあたる。

### 8. 号数の目安値は3号・5号・10号に限る

- 号数と開花高度・開花直径の対応は出典によって値が異なる。複数の出典で確認できた3号・5号・10号だけを目安値として持ち、それ以外は開花高度・開花直径の直接指定で扱う。
- 目安値の表は `domain/` に定数として置き、仕様の表と一致することを単体テストで確認する。

### 9. スマホ対応は画面の配置と描画負荷の調整にとどめる

- 画面幅が狭いときは、パネルを地図の下部に折りたためるようにする。
- Cesium の `requestRenderMode` を有効にし、変化がないときは再描画しない。
- 操作の入力は Pointer Events で扱い、マウスとタッチを同じ処理にする。

### 10. 用語は CONTEXT.md に記録する

撮影地点、地上高、花火、打上地点、号数、開花高度、開花直径、開花範囲、俯瞰モード、一人称モードを、`domain-modeling` スキルに沿ってリポジトリ直下の `CONTEXT.md` に定義する。コード上の名前もこの用語に揃える。

## Risks / Trade-offs

- [PLATEAU 配信サービスが停止したり、仕様が変わったりする] → カタログ API の呼び出しを `data/` に閉じ込め、取得の失敗は仕様どおり画面に通知する。恒久的な対策（自前ホスティングなど）は必要になった時点で別の change にする。
- [LOD1 の箱型は、尖塔や斜めの屋根の建物では実物より大きく遮る] → 「見えない」と判定する側に倒れるので、見えると誤認する危険はない。LOD2 の採用は後で検討する。
- [3Dデータにない樹木や対象地域外の建物があるため、実際には遮られるのに見えると表示される] → 仕様の注記で知らせる。
- [東京23区と横浜市の全区の tileset を一度に追加すると、読み込みが重くなる] → 3D Tiles は表示中の範囲だけを詳細に読み込むため、全区を追加しても読み込みは視野内に限られる。手動確認で重い場合は `maximumScreenSpaceError` を調整する。
- [CesiumJS はパッケージが大きく、初回の読み込みが遅い] → MVP では受け入れる。

## Migration Plan

新規のアプリのため、移行はない。公開・デプロイは本変更の範囲外とし、ローカルの開発サーバーで確認する。

## Open Questions

なし。出典表示の文言は実装時に各利用条件で確認し、地図上のクレジットとして表示した（建物: PLATEAU サイトポリシーに沿った出典と加工の旨、地形: `layer.json` の attribution、背景地図: 地理院タイル）。
