# Design

## Context

- 一人称モードは `map/firstPerson.ts` の `FirstPersonController` が担う。roll を 0 に固定し、`camera.setView` で方位と仰角だけを変える。視野は Cesium の既定値のまま（MVP の design.md 決定6で、レンズの画角は本 Issue に先送りした）。
- Cesium 1.146 の `PerspectiveFrustum.fov` の既定値は 60° で、画面の幅が高さより大きければ水平、そうでなければ垂直の視野として使われる（`@cesium/core/Source/PerspectiveFrustum.js` の `fov` の説明、`@cesium/engine/Source/Scene/Camera.js` の初期化）。
- ドラッグ量から視線の回転量への換算は `frustum.fovy` を使っている（`firstPerson.ts` の `drag`）。そのため、視野を変えれば換算も自動で追従する。
- 状態は `state/appState.ts` の `useReducer` で1か所に持ち、`map/` は状態を Cesium の表示へ一方向に反映する（MVP の design.md 決定2）。

## Goals / Non-Goals

**Goals:**

- 画角・視野・枠の大きさの計算を、Cesium に依存しない純粋な関数として持ち、単体テストで検証する。
- 画角枠と実際に写る範囲が、画面の大きさや向きによらず一致する。

**Non-Goals:**

- 画角枠を 3D 空間の物体（Entity）として描くこと。
- 一人称モード以外での画角の表示（俯瞰モードでの視錐台の表示は #6 で扱う）。

## Decisions

### 1. 画角枠は画面中央に重ねる 2D の長方形として描く

```
  画面（透視投影, roll = 0）
  +------------------------------------------+
  |   +----------------------------------+   |
  |   | 24mm                             |   |
  |   |      +--------------------+      |   |
  |   |      | 50mm               |      |   |
  |   |      |        +           |      |   |  + = 視線の中心
  |   |      +--------------------+      |   |
  |   +----------------------------------+   |
  +------------------------------------------+

  枠の幅 / 画面の幅   = tan(レンズの水平画角 / 2) / tan(画面の水平視野 / 2)
  枠の高さ / 画面の高さ = tan(レンズの垂直画角 / 2) / tan(画面の垂直視野 / 2)
```

- Cesium の画面は歪みのない透視投影である。roll が 0 のとき、同じ位置・同じ向きで画角だけ狭いレンズが写す範囲は、画面中央の長方形とちょうど一致する。そのため、地図の領域に重ねた HTML 要素の長方形で正確に描ける。枠の大きさは、画面に対する割合（%）で指定する。
- 重ね表示は `pointer-events: none` にし、一人称モードのドラッグ操作を妨げないようにする。
- 却下した代替案: 視線の先に 3D の長方形（Entity）を置く方法。視線の向きが変わるたびに位置を更新する必要があり、建物に隠れる・距離で見え方が変わるなど、「写る範囲」の表現としては不正確になる。

### 2. 画角・視野・枠の割合の計算は `domain/lens.ts` に純粋な関数として置く

- 焦点距離の定数 `FOCAL_LENGTHS = [24, 28, 35, 40, 50, 75, 85, 100, 200]` と、フルサイズ（36 x 24mm）の寸法から、水平・垂直の画角を求める関数を置く。
- 画面の縦横比と表示中の焦点距離から、画面の視野（Cesium の `fov` に渡す、長い辺の方向の視野）を求める関数を置く（決定3）。
- 視野と縦横比から、各画角枠の幅と高さの割合を求める関数を置く。
- 重ね表示（ui）と一人称モードのカメラ（map）の両方が同じ関数を使う。これにより、枠の大きさと実際の視野が食い違わない。
- 画角は角度ではなく tan(半角) のまま扱う部分が多いが、内部の計算方法は実装の詳細とする。テストでは仕様の値（50mm で 約39.6° / 約27.0° など）を確認する。

### 3. 画面の視野は「最も広い画角枠が余白つきで収まる視野」と既定の 60° の大きい方にする

```
  aspect = 画面の幅 / 画面の高さ
  必要な tan(画面の水平視野/2) >= tan(枠の水平画角/2) / FILL
  必要な tan(画面の垂直視野/2) >= tan(枠の垂直画角/2) / FILL
  （tan(垂直/2) = tan(水平/2) / aspect の関係で、長い辺の方向の視野に揃えて比べる）

  fov = max(60°, 表示中のすべての枠について必要な長い辺の視野)
```

- `FILL` は、最も広い画角枠が画面の幅・高さに占める割合の上限とする（0.9 程度）。枠の線とラベルが画面の端で切れないようにするためである。値は実装時に見た目で調整し、定数として持つ。
- 既定より狭くしない理由: 周りの景色と並べて写る範囲を確かめることが目的であるため。また、LOD1 の箱型の建物は拡大しても情報が増えない（探索時の合意）。
- 計算例: 16:9 の横長画面で 24mm を表示すると、垂直画角 53.1° が収まる条件で水平視野は約 83°（FILL = 1 の場合）から 90° 前後になる。縦長のスマホ画面では、長い辺（垂直）の視野が 110° 前後まで広がる。

### 4. 視野の適用は `FirstPersonController` が受け持ち、終了時に元の視野へ戻す

- `FirstPersonController` に、表示中の焦点距離を受け取って視野を再計算するメソッドを加える。`CesiumMap` は、状態の焦点距離が変わったときにこのメソッドを呼ぶ。
- 画面の大きさが変わったとき（ウィンドウのサイズ変更やスマホの回転）は、縦横比が変わるため視野を再計算する。canvas の大きさを `ResizeObserver` で監視する。
- 一人称モードに入る前の `fov` を保存しておき、`destroy` で視点と同時に復元する。こうして俯瞰モードの視野を既定に戻す。
- 視野を変えても `setView` の位置と向きは変えない。ドラッグの換算は `frustum.fovy` から求めているため、変更は要らない。

### 5. 重ね表示のコンポーネントは自分で大きさを測る

- `ui/LensFrames.tsx` を地図の領域に重ね、`ResizeObserver` で自身の大きさ（= canvas と同じ大きさ。どちらも地図の領域いっぱいに置かれている）を測る。決定2の関数で、視野と枠の割合を求める。
- Cesium から視野を読み戻さず、同じ入力（縦横比と焦点距離）から同じ純粋な関数で計算する。これにより、React 側と Cesium 側の間で状態を同期しなくて済む。
- 却下した代替案: `CesiumMap` が Cesium の現在の `fov` を React の状態に上げる方法。`onViewDirectionChange` と同様の経路を増やすことになり、描画のたびに状態が更新される。

### 6. 状態は表示中の焦点距離の集合だけを持つ

- `AppState` に `shownFocalLengths: readonly FocalLength[]` を加え、action `toggleFocalLength` で切り替える。並び順は `FOCAL_LENGTHS` の順に正規化し、表示の順番が操作の順番に左右されないようにする。
- 切り替えは俯瞰モードと一人称モードのどちらでもできるようにする。一人称モードで見ながら比べられるようにするためである。表示は一人称モードの間だけとする。
- `FocalLength` は `FOCAL_LENGTHS` の要素の型（`(typeof FOCAL_LENGTHS)[number]`）とし、定番以外の値が入らないようにする。

### 7. パネルに「画角枠」の区画を置き、焦点距離ごとの切り替えボタンを並べる

- 9つのボタンを `aria-pressed` 付きのトグルにする。既存の道具ボタンと同じ見た目の規則に揃える。
- 区画に「35mm判フルサイズ換算の焦点距離です。画角枠は一人称モードで表示されます」の旨の短い説明を置く。

### 8. 焦点距離は枠の色とラベルで区別する

- 焦点距離ごとに固定の色を割り当てる。暗い空や明るい建物のどちらの上でも見えるように、色の線に暗い縁取り（影）を付ける。
- 枠の左上の内側に「24mm」のようなラベルを置く。色だけに頼らず、ラベルで判別できるようにする（仕様の要件）。
- 望遠の枠は小さいため、ラベルは枠の外（上側）にはみ出してよいことにする。

### 9. 用語を CONTEXT.md に追加する

`domain-modeling` スキルに沿って、次を定義する。

- **焦点距離**: 35mm判フルサイズ換算の焦点距離。
- **画角**: ある焦点距離のレンズで写る範囲の角度（水平・垂直）。
- **画角枠**: 一人称モードで、ある焦点距離の画角で写る範囲を示す画面上の長方形。
- **視野**: 一人称モードの画面全体に映る範囲の角度。画角と区別して使う。

## Risks / Trade-offs

- [24mm を表示すると視野が 90°〜110° 前後まで広がり、画面の端の景色が引き伸ばされる] → 透視投影としては正しく、画角枠の中は実際に写る範囲と一致する。見え方が気になる場合は、FILL の調整やズーム操作（範囲外）を別途検討する。
- [200mm の枠は既定の視野で画面の約 16% の大きさしかなく、枠の中の様子が見にくい] → 既定より狭くしない方針として受け入れる（探索時の合意）。
- [フルサイズ以外のセンサーで換算値を入れても、縦横比 4:3 などのセンサーでは写る範囲の形が 3:2 の枠と一致しない] → 仕様で「フルサイズ・横位置」と定めており、パネルの説明で換算値である旨を示す。
- [重ね表示と canvas の大きさが一致しないと枠がずれる] → どちらも地図の領域いっぱいに置く既存のレイアウトを前提にする。手動確認で、ウィンドウのサイズ変更とスマホの回転の後に枠と景色が合っていることを確かめる。
